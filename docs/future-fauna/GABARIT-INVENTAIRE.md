# Gabarit du dossier animalier — à remplir dans L19

**État : gabarit documentaire, pas inventaire déjà vérifié. Aucun chargement par le jeu.**

## Fiche d’information

| Champ | Contenu à relever |
|---|---|
| Identifiant et définition | Nom documentaire stable ; sens exact et usage futur envisagé. |
| Source | Lot, contrat, chemin et symbole/section ; commit et version. |
| Disponibilité | Vérifiée / documentée non vérifiée localement / prévue / absente. |
| Repère | Monde, dimension, axes, origine et type de coordonnées. |
| Valeur | Unité, catégorie, plage réellement documentée, résolution et approximation. |
| Temps | Référence annuelle, génération initiale, snapshot daté ou état courant. |
| Manquants | Inconnu, non généré, aucun candidat et zéro explicitement différenciés. |
| Limites | Ce que cette information ne permet pas d’affirmer. |
| Contrôle futur | Vérification locale et propriétaire du contrôle avant usage par un animal. |
| Preuve | Référence consultée ; ne pas inventer un résultat de test. |

## Structure du dossier final

`inventaire.md` répertorie les familles ; `dictionnaire.md` définit les entrées ; `poi-candidats.md` décrit seulement les catégories potentielles ; `responsabilites.md` porte limites et besoins futurs ; `revue-finale.md` identifie baseline, contrôles et passation.

Ne pas remplir les coordonnées, unités, propriétés de classes ou disponibilités depuis une supposition. Une absence documentée est acceptable et ne déclenche pas du développement runtime dans L19.
