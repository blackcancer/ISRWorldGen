# WorldGen.Tests — isolation des sources générées (CS0579)

Base examinée : `ebe48f27d34ef5a5ad897204168bb42bd822c1f6`.
Intervention demandée directement sur `main` par l'utilisateur.

## Diagnostic et correction

Le projet SDK inclut implicitement les sources C# sous son répertoire. Les
exclusions des sorties actives ne garantissent pas l'exclusion des `bin/obj`
imbriqués (anciens projets de laboratoire), ni des anciens répertoires lorsque
`BaseIntermediateOutputPath`/`BaseOutputPath` changent. Des AssemblyInfo générés
peuvent donc être compilés en plus de ceux du projet courant, provoquant les
huit doublons signalés : TargetFramework, Company, Configuration, FileVersion,
InformationalVersion, Product, Title et AssemblyVersion.

`WorldGen.Tests.csproj` ajoute `**/bin/**;**/obj/**` à `DefaultItemExcludes`.
Les exclusions existantes, les sources de tests, les références et les propriétés
d'assembly sont conservées. Ni GenerateAssemblyInfo ni
GenerateTargetFrameworkAttribute ne sont désactivés. Les fichiers générés ne
sont pas modifiés, et aucune suppression du répertoire de travail n'est requise.
Aucun appel API Vintage Story, framework, dépendance NuGet ou code du mod change.

## Régression reproductible

`tools/test_testproject_inputs.py` crée des fixtures temporaires avec des copies
exactes du csproj et des props/global.json. MSBuild évalue le véritable projet :
ce n'est pas une réimplémentation de ses globs en Python. Les résidus sont placés
aux niveaux racine et imbriqués ; les noms de répertoires légitimes `binary` et
`objects`, ainsi qu'un AssemblyInfo manuscrit valide, doivent rester inclus.
Les exclusions explicites historiques restent vérifiées.

Le compilateur témoin reçoit exactement les éléments Compile ainsi évalués,
sans dépendances au jeu. Il doit reproduire chacune des huit erreurs CS0579 sur
la baseline puis compiler sur le candidat, également lors d'une seconde build.
L'évaluation design-time et les sorties déportées sont couvertes. Le workflow
exécute cette matrice sous Windows/Linux, Debug/Release, avec le SDK du dépôt.

Les journaux et résultats exécutés sont ceux de GitHub Actions pour le commit
concerné. La syntaxe Python a été vérifiée à l'édition ; aucun résultat .NET
local n'est revendiqué. Une campagne verte qualifie l'évaluation du projet et le
compilateur témoin, pas la solution complète avec les DLL natives ni le jeu.
`registry/state.json`, les profils Visual Studio et les sauvegardes sont intacts.
Le contenu exact des fichiers ignorés présents sur la machine de l'utilisateur
n'a pas été lu : le scénario de contamination est reproduit sur fixtures.
