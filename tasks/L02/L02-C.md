# L02-C — Définir profils d’échelle et contrôle des motifs
**Sous-lot délégable · statut initial BACKLOG · un agent propriétaire · contrats version 1.0**

## Objectif et résultat attendu
Définir les presets de laboratoire, équilibré et vastes expéditions, leur budget vertical et leurs validations. Ajouter diagnostics d’alignement/periodicité et témoins Voronoï volontairement visibles.

**Livrable attendu.** Profils de départ versionnés, validateurs et rapport de sensibilité des détecteurs. Les dimensions proposées ne deviennent pas la préférence définitive du joueur.

## Points de vigilance spécifiques
Une carte géométriquement valide peut être visuellement mauvaise. Le test de motifs exige aussi une revue, pas un seuil FFT proclamé universel.

## Travail demandé
Établir les entrées/sorties et les cas de défaut du périmètre ; écrire d’abord les tests analytiques ou probes nécessaires. Implémenter la solution bornée, documenter ses décisions et conserver les mesures utiles. Exécuter ensuite les cas ci-dessous et le minimum de régression des consommateurs touchés. Ne pas étendre discrètement le périmètre pour finir un module voisin.

## Acceptation
Exigences : R02-05, R02-06. Tests à exécuter : T02-05, T02-06. Les scénarios, oracles et tolérances sont dans [tests/T02.md](../../tests/T02.md). Aucun de ces cas n’est déjà réussi. Les tests nécessitant le moteur doivent être effectués sur le processus réel, avec la version auditée ; un mock ne suffit pas.

## Passation à l’intégrateur
Fournir le commit/base, les fichiers changés, les versions de contrat, résultats exacts, mesures et preuves. Utiliser [templates/HANDOFF.md](../../templates/HANDOFF.md). Séparer ce qui est implémenté, vérifié ou bloqué. Un agent ne met pas lui-même le statut global à DONE ; l’intégrateur relit, fusionne, relance la régression et actualise le registre.
