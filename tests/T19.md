# T19 — Scénarios d’acceptation de L19

**Définitions uniquement : tous ces scénarios commencent à NOT_RUN dans cette livraison.**

Ces contrôles portent sur le futur dossier complété et le diff de L19, pas sur un animal simulé. Leur inscription ici ne signifie pas que l’inventaire de la baseline est réalisé.

## T19-01 — Périmètre strictement documentaire

Propriétaire : **L19-A**. Exigence : **R19-01**. Niveau : Revue documentaire. État fourni : **NOT_RUN**.

Méthode : Comparer le diff de L19 aux chemins autorisés ; rechercher ajouts de runtime, assets, références et services.

Oracle : Aucun changement exécutable. Cas négatif : un handler de soif ou un index POI ajouté doit faire échouer la revue.

## T19-02 — Couverture des informations

Propriétaire : **L19-A**. Exigence : **R19-02**. Niveau : Revue documentaire. État fourni : **NOT_RUN**.

Méthode : Lire la matrice source/usage/limite et contrôler toutes les familles de S19.

Oracle : Aucune famille omise sans justification. Cas négatif : neige/glace ou végétation non traitée.

## T19-03 — Provenance et disponibilité

Oracle : Aucune valeur ou API inventée. Cas négatif : information seulement prévue présentée comme implémentée.

## T19-04 — Potentiel versus état courant

Propriétaire : **L19-B**. Exigence : **R19-04**. Niveau : Revue documentaire. État fourni : **NOT_RUN**.

Oracle : Le dossier ne garantit ni stock ni navigation. Cas négatif : eau potentielle assimilée à abreuvement possible.

## Preuves

Chaque rapport nomme le commit, les versions, les entrées, la méthode réellement exécutée, le résultat et ses limites. Pour un test runtime : seed, profil, monde de test, ordre/workers, commandes et artefacts ; pour une revue : références contrôlées, échantillon et cas négatifs. Un test non exécuté reste NOT_RUN ; les preuves historiques ne sont jamais écrasées.
