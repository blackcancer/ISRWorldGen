# T19 — Scénarios de L19-D

Règles communes et index : [T19](../T19.md). Ce fichier est la définition canonique des scénarios ci-dessous. Aucun test du mod n’est déclaré exécuté par sa présence.

## T19-09 — Collecte sans influence sur le monde

**Propriétaire : L19-D · exigence : R19-09 · nature : technique ; moteur/backend réel lorsque indiqué.**

Fixture : Même monde et mêmes producteurs, collecte activée/désactivée.

Oracle positif : Comparer snapshots/hashs de blocs et décisions monde ; catalogue créé sans consommateur. Produire les cartes pertinentes de couverture.

Contrôle négatif : Une consommation du RNG worldgen par le collecteur ou une différence de placement doit être détectée.

Preuves : baseline/versions, commande ou protocole, résultat exact et artefacts référencés dans le worklog ; captures et instrumentation natives pour le runtime, cartes quand la sortie est spatiale.

## T19-10 — Publication et couverture

**Propriétaire : L19-D · exigence : R19-10 · nature : technique ; moteur/backend réel lorsque indiqué.**

Fixture : Placement accepté, rejeté, interrompu et régions partiellement générées.

Oracle positif : Plans et reçus se distinguent ; seule la partie validée est publiée comme GeneratedBaseline ; coverage par couche exacte.

Contrôle négatif : Un arbre rejeté, un fragment non terminé ou une référence non persistée ne peut pas être annoncé comme généré avec coverage complet.

Preuves : baseline/versions, commande ou protocole, résultat exact et artefacts référencés dans le worklog ; captures et instrumentation natives pour le runtime, cartes quand la sortie est spatiale.

## T19-11 — Identité spatiale déterministe

**Propriétaire : L19-D · exigence : R19-11 · nature : technique ; moteur/backend réel lorsque indiqué.**

Fixture : Frontière de quatre régions, coordonnées négatives et deux dimensions.

Oracle positif : Même identité logique, fragments cohérents et aucun doublon selon ordre d’arrivée/threads ; sérialisation identique à versions identiques.

Contrôle négatif : Injecter division tronquée, mélange de dimension, ordre de dictionnaire et double référencement : chaque défaut est détecté. Cartes de coutures requises.

Preuves : baseline/versions, commande ou protocole, résultat exact et artefacts référencés dans le worklog ; captures et instrumentation natives pour le runtime, cartes quand la sortie est spatiale.

## T19-12 — Persistance et reprise sûre

**Propriétaire : L19-D · exigence : R19-12 · nature : technique ; moteur/backend réel lorsque indiqué.**

Fixture : Backend C05 réel, interruption aux étapes de publication.

Oracle positif : Tester écriture/relecture/restart, corruption/checksum, taille avant allocation, page manquante, annulation et reconstruction d’index.

Contrôle négatif : Une panne entre données et manifeste ne doit pas produire une région entièrement disponible ni écraser le dernier snapshot valide.

Preuves : baseline/versions, commande ou protocole, résultat exact et artefacts référencés dans le worklog ; captures et instrumentation natives pour le runtime, cartes quand la sortie est spatiale.

## T19-13 — Versions et adoption tardive

**Propriétaire : L19-D · exigence : R19-13 · nature : technique ; moteur/backend réel lorsque indiqué.**

Fixture : Monde avec L19 sans consommateur puis ajout ; ancien monde sans L19.

Oracle positif : Premier cas : données immédiatement retrouvables. Ancien monde : import metadata-only exact ou LegacyMissing explicite, sans changement de blocs.

Contrôle négatif : Refuser reconstruction silencieuse avec une autre version/seed ou analyse des blocs actuels présentée comme état initial.

Preuves : baseline/versions, commande ou protocole, résultat exact et artefacts référencés dans le worklog ; captures et instrumentation natives pour le runtime, cartes quand la sortie est spatiale.
