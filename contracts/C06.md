# C06 — Façade Vintage Story et propriété des passes


## Surface vérifiée
Les signatures observées dans l’API publiée sont :
```csharp
void InitWorldGenerator(Action handler, string forWorldType);
void MapRegionGeneration(MapRegionGeneratorDelegate handler, string forWorldType);
void MapChunkGeneration(MapChunkGeneratorDelegate handler, string forWorldType);
void ChunkColumnGeneration(ChunkColumnGenerationDelegate handler, EnumWorldGenPass pass, string forWorldType);
IWorldGenHandler GetRegisteredWorldGenHandlers(string worldType);
```
Ces déclarations décrivent l’API consultée, pas une implémentation prête à coller dans le mod. Leur disponibilité locale doit être compilée au lot L00. Source : API-01.

## Adaptateurs internes à créer
`NativeMapAdapter` transforme des champs modèle en cartes natives après audit du format et du padding. `ColumnWriter` transforme un ColumnPlan en couches solides/fluides et maintient les métadonnées. `WorldgenHookAdapter` possède les inscriptions/retraits autorisés. `NativeMaterialCatalog` résout les codes d’actifs de manière stable pour une session.

Le tableau des passes contient pour chaque handler identité observée, événement, enum, ordre, données lues/écrites, thread, action et test associé. L’identité ne repose pas uniquement sur une chaîne fragile de nom de méthode si une référence de type/delegate stable est disponible. Toute mise à jour du jeu invalide l’audit de remplacement jusqu’au test.

## Sémantiques de cartes
WorldGenTerrainHeightMap décrit le terrain avant Vegetation, fond marin inclus. RainHeightMap dépend des blocs non perméables à la pluie. TopRockIdMap décrit la roche sommitale. YMax couvre le plus haut bloc non vide. Leur validation s’effectue à l’étape appropriée et tient compte des écritures ultérieures.

ClimateMap doit recevoir l’encodage et la référence thermique attendus ; BiomeMap n’est pas une API de biomes active supposée. TerrainMap/RiversMap exigent identification de leurs formats et consommateurs. Moddata serveur n’est pas automatiquement synchronisée au client. Sources API-05/API-06.

## Contraintes
Pas de WipeAllHandlers global, pas de modification de monde désactivé, pas de régénération automatique de chunks existants. Les handlers natifs retenus doivent respecter les réservations ou être adaptés. Les bibliothèques, assets côté client, et éventuel Harmony sont déclarés explicitement, jamais ajoutés « au cas où ».

Les API de stockage StoreData/GetData de ISaveGame et SetModdata/GetModdata des régions sont vérifiées mais ne prouvent pas des garanties transactionnelles. Les noms et la casse exacts suivent les assemblages testés. Source API-07.
